## How to Use This List

### For Contributors
1. Pick an issue from the **Critical** or **Medium** sections
2. Create a spec in `specs/NNN-slug/` (see `TEMPLATE-spec.md`)
3. Create a branch: `git checkout -b fix/issue-number-name`
4. Implement the fix
5. Test in CI: `gh run watch`
6. Submit PR with reference to this tracker

### For Maintainers
- Review this list before each release
- Prioritize **Critical** issues (audio, loader, thread safety)
- Quick wins in **Low Priority** (cleanup, renaming) can be bundled with other changes

### For AI Agents
Use the priority and effort columns to decide:
- **High priority + low effort** = good candidate for immediate fix
- **High impact + known approach** = good candidate for spec-driven implementation
- **Complex or risky** = create spec first, review with team
